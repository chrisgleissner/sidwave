# Changelog

All notable changes to `sidwave` are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Before 1.0.0, a minor version may contain breaking changes.

## Unreleased

### Added

- ABC 2.1 subset import (`.abc`) through `sidwave convert` and the library function `importAbc`: tune selection by `X:` number, keys and modes, voices, repeats with variant endings, ties, broken rhythm, tuplets and fields changed in the tune body, with counted losses for skipped notation and for notes beyond the voices. See `doc/interchange.md`.
- `sidwave convert score.yaml score.bas` writes a Commodore BASIC V2 program with checksummed DATA records that plays up to three voices on the SID at `$D400`: for each note of the score the pitch, waveform, pulse width and envelope that the compiled player uses, timed with the jiffy clock `TI`. Notes in passages that are too dense for BASIC are delayed and reported, a program larger than BASIC RAM exits 5 with a `--seconds` value that fits, and `--seconds` writes the first part of a score. See `doc/interchange.md` for the measured timing error and the losses.
- `sidwave play <file>` plays a score, a PSID or RSID file, or any input that `convert` reads: through the local libsidplayfp engine into an installed audio player (default), through VICE (`--target vice`), or through the Ultimate REST API (`--target u64 --host <h>`, password from `SIDWAVE_U64_PASSWORD`). `--song`, `--solo`, `--mute`, `--from-bar` and `--loop-section` select what is played.
- `sidwave watch <score>` recompiles the score on every save, reports errors and lint findings with line and column, and restarts playback. `--no-play` only checks; `--json` prints one object per event.
- Library entry point `sidwave/play`. The engine render request has a new option `onSamples`, which streams the PCM in slices and waits for the consumer.
- `compile --target game --format asm [--asm 64tass|acme|kickass|ca65]` writes a self-contained assembler include with the player and data bytes, the symbols and a header describing the call API. `--symbols` also accepts `64tass`. `--reloc` writes a verified page relocation table, with separate tables for moving the player and a separate data block, and `--max-cycles n` writes nothing and exits 5 when a play call needs more than `n` cycles. Library: `renderSidwaveGameInclude`, `sidwaveRelocationTable`, the `maxCycles` option and `SidwaveGameCycleLimitError`. See `doc/authoring.md`.
- Song names with line breaks or other control characters can no longer leave the comment lines of the symbol files.
- `sidwave sid info|edit|player`, `sidwave songlengths lookup|verify|write` and `sidwave stil parse|query` for HVSC work, and the library entry point `sidwave/hvsc` (`editSidHeader`, `writeSonglengthsEntry`, `verifySonglengths`, `lookupSonglengthEntries`, `parseStil`, `queryStil`, `identifySidPlayer`). `sid edit` patches only the bytes of the named header fields (title, author, released, songs, start song, speed, clock, SID models, second and third SID, flags, version, addresses, relocation range), validates the result against the PSID specification, raises the header version with a warning when a field needs it, and prints the old and new Songlengths MD5 keys; `--dry-run` shows the field changes. `songlengths write` adds or updates an entry in Songlengths.md5 or Songlengths.txt and changes only the lines it touches, including `--from-md5` to carry the times of an edited file over. `songlengths verify` checks every entry against the files of an HVSC tree. `sid player` reads a SIDId signature file from a path the user gives (none is shipped). `--hvsc` defaults to `HVSC_ROOT`. See `doc/hvsc.md`.
- `legacyMd5ForSonglengths` (the key of the old Songlengths.txt format) and `scanSonglengths` (entry offsets for format-preserving edits). `lookupStil` and `STIL_MAX_CHARS` moved to the module `stil.ts` and are still exported from `sidwave/analyze`. `parseSonglengths` is about twice as fast on the full HVSC file (140 ms instead of 280 ms CPU on a cold start).
- JCH NewPlayer 20.G import: `sidwave import` reads the editor image (PRG or unpacked PSID loaded at `$0F00`, mark `20.G`): order lists, sequences, instruments, wave and pulse tables, tempo and groove, with vibrato, portamento and slides approximated. Library: `parseJch`, `importJch`. `sidwave convert song.mod song.sid` and the same for JCH images work through the format registry (`formats/mod.ts`, `formats/jch.ts`).
- ProTracker MOD import: `sidwave import tune.mod` reads 31-sample (`M.K.`, `M!K!`, `FLT4`, `FLT8`, `4CHN`, `6CHN`, `8CHN`, `nnCH`, ...) and 15-sample modules, follows jumps, breaks, loops, delays, speed and tempo, reduces four or more channels to three voices per SID (`--sids n` keeps more), maps samples to waveforms, ADSR and library drums, maps arpeggio, slides, tone portamento, vibrato, volume, note cut and delay, reports every unmapped effect by count, and with `--quality` measures note F1, onset error and duration overlap against the notes of the MOD. Library: `parseMod`, `importMod`, `measureModQuality`, `playRows`, `analyzeSample`. Mappings, losses and measurements are in `doc/interchange.md`.
- SID-Wizard files: `sidwave import` reads `.swm`, `.sws` and `.swi` (`--subtune`), `sidwave export --format swm` writes a module for the expressible subset and `--format swi --instrument` an instrument file. Library: `parseSwm`, `writeSwm`, `parseSwi`, `writeSwi`, `importSwm`, `importSwi`, `exportSwm`, `exportSwi`. Mappings, losses and the comparison with the SID-Wizard player are in `doc/interchange.md`.
- `sidwave reconstruct <trace> --from vice-dump|siddump` recovers a score from a VICE `-sounddev dump` text (exact register writes) or a siddump table (approximate, one row per frame), and `sidwave export <score> --format vice-dump` writes the SID writes of a compiled score in the VICE dump text format. Library: `parseViceDump`, `parseSiddump`, `exportViceDump`, `reconstructFromTrace`.

- Added `sidwave convert <in> [<out>]`: converts between SIDWave scores, MIDI, MusicXML, GoatTracker, Furnace, PRG, PSID, WAV and the event list in one step. The input format is detected from the content. The report lists every loss with a code, a severity and a count; `--strict`, `--dry-run`, `--verify` (note F1, onset error, octave shifts, voices dropped), `--keep-score`, `--report` and `--voices` are available. A `.sid` input is read by reconstruct.
- Formats are discovered from `interchange/formats/`: a new format is one new file. SID-Wizard (`sidwizard`, read and write), VICE dump (`vice-dump`, read by reconstruct and write) and siddump (read by reconstruct) are registered there.
- Added `sidwave formats` and `sidwave info <file>`, and `convert()`, `detectFormat()` and `listFormats()` at the package root. A format registry (`interchange/registry.ts`) makes a new format a one-file addition (`interchange/formatsExtra.ts`).
- Added the conversion test matrix: every importer and exporter pair on committed fixtures, with golden losses, per-pair quality thresholds in `doc/interchange.md`, typed errors for truncated and corrupted files, and a chain-equals-two-step identity check.
- Added SID Factory II `.sf2` import and export for driver 11.xx (`sidwave import song.sf2`, `sidwave export score.yaml --driver sf2driver11_05.prg`). Import is found by the file id or extension; export needs a user-supplied driver, because SIDWave does not ship the driver. Drivers 12 to 16 and NP20 are refused with a message that points to `sidwave reconstruct`. Verified against the driver inside the driver 11 example songs.
- `sidwave convert` reads and writes CheeseCutter (`.ct`) and SID Factory II (`.sf2`); a target of these formats needs `--driver <file>`. SID Factory II export writes instrument wavetables as wave table rows and arpeggio, vibrato and local ADSR as commands on the notes, so songs that import also export, and the last note of a song keeps its length. The stereo `.ct` message names what is not supported yet.
- Added CheeseCutter 2.x `.ct` import and export (`sidwave import song.ct`, `sidwave export score.yaml --driver song.ct`). Import is found by magic or extension; export needs a user-supplied driver (a `.ct` file or the player binary), because SIDWave does not ship CheeseCutter's player. Verified against the player inside the example songs.
- Added `sidwave/retarget` and `sidwave retarget`: convert a score between PAL and NTSC, 6581 and 8580, and SID counts. Every change is reported as exact, approximate or dropped with measured numbers (timing per event kind, filter cutoff deviation, voices kept and dropped).
- `sidwave retarget` accepts `--budget-bytes`, `--budget-cycles` and `--allow-changes`: music-preserving steps run first and are checked on the register trace, lossy steps only on request, and a budget that cannot be met gives exit 1 with the best numbers reached.
- npm package `sidwave`: language, parser, lint, compiler to PRG and PSID, generator, examples and the `sidwave` command. It is extracted from c64bridge with the history of the moved files. It is not published yet.
- Added `sidwave/sid-file` and `sidwave/songlengths`: PSID/RSID v1-v4 reader and writer, HVSC Songlengths.md5 parser.
- Added `sidwave/engine` (libsidplayfp-wasm render and cycle-exact trace, optional peer dependency) and `sidwave/verify` (T0, T1 and A0 comparison).
- Added the game build (`compileSidwave` with `target: "game"`, `sidwave compile --target game`): the player at a chosen origin with optional separate data, symbol files, a register contract and cycles measured on a bundled 6502 interpreter. Existing PRG and PSID output is unchanged.
- A committed launcher `bin/sidwave.js`. Previously `npx sidwave` failed in a fresh clone: npm creates the workspace bin link during `npm ci`, before `dist/` exists, and does not create a link whose target is missing. The launcher exists in the clone, so the link is always created and loads `dist/bin.js` once the build has run.

- `sidwave verify`, `render`, `trace` and `sid-info` commands (`sid-info` is now an alias of `sid info`); `--json` on every command; `--progress`, `--max-seconds`, `--max-records`, `--max-bytes`; SIGINT cancellation. Library functions `verifyTunes`, `renderTune`, `traceTune`, `sidInfo`, `loadTune`, `classifyError`.
- Verification level A1 (`compareAudioA1`, `data/verify/a1-rules.json`): a windowed audio comparison with thresholds fitted on score-level mutations. Status: approximate (held-out false accepts 15.3 %, false rejects 22.2 %; see `data/verify/a1-limitations.md`). `scripts/calibrate-a1.mjs` and the mutation generator are included.
- `sidwave reconstruct` and `reconstructSid` (`sidwave/reconstruct`): recover a SIDWave score from a SID tune, recompile it and compare the two traces call by call. The report carries the horizon, call rate, unsupported features, strict and register-state F-diff verdicts and language-extension candidates with reproducers. Exit 1 with `ok: false` when the strict F-diff is not exact.

- `sidwave export` and `sidwave import` and the library entry point `sidwave/export`: structured event export (`sidwave.events/1`), Standard MIDI File import and export, MusicXML (partwise) import and export, GoatTracker `.sng` import (`GTS!`, `GTS2`, `GTS3` to `GTS5`) and GTS5 export, Furnace `.fur` import and export (C64 chip), and `sidwave render --stems`. Each mapping and its losses are in `doc/interchange.md`. The GoatTracker importer is checked against `gt2reloc` of GoatTracker 2.77; the Furnace export has not been loaded by Furnace itself.
- Composer 2, opt-in with `generateSidwave({ composer: 2, profile })`: 33 profiles with form, functional harmony, melody, motif development, counterpoint with a rule checker (`checkCounterpoint`), groove and drum patterns, and instrumentation on at most three voices per SID under a measured cycle budget. The default generator and its output are unchanged (`test/composeBaseline.test.mjs` pins them).
- `sidwave complete` and `completeScore`: continue, harmonise, accompany and fill-section on an existing score. Target voices must be free; protected voices keep their SID register writes, verified by tracing both scores. `verifyProtected`, `analyseScore`, `measureScore`, `traceDocument` are exported. The result lists what is not compared (the ring-out tail when new entries follow, and the hard restart before a continued voice).
- `scripts/evaluate-composer.mjs` and `data/compose/` (profile list, evaluation of composer 2 against the version 1 generator on proxy measures).
- `sidwave analyze` and `analyzeScore`/`analyzeSid` (`sidwave/analyze`): structural analysis of a score or SID tune (key and mode, metre, form, motifs, voice use, techniques, resources). Every fact is marked `observed` (trace or score) or `inferred` (method named).
- `sidwave compare` and `compare`: F-diff (total, per class, per voice), the verification ladder with the A1 calibration status, and the semantic diff of two scores.
- `sidwave isolate` and `isolateVoice`: one voice alone (or all but one) as a WAV by reconstruct-and-recompile, with the coupling (filter, sync, ring, sample playback) that makes the result non-additive.
- `sidwave preserve` and `createPreservation`/`verifyPreservation`: a preservation bundle (score, checksums, configuration, tool identities, horizon, verdict, ambiguities, rights) with a manifest `preservation.json` that verifies offline. The original SID is stored only with `--include-original --rights-permitted`.
- `sidwave extract-instruments` and `extractInstruments`: the instruments of a score or of a reconstruction as a SIDWave 1.4 library with provenance; `checkInstrumentReuse` compares an extracted instrument in a new score with the source.
- Documentation: `doc/analysis.md`, `doc/preservation.md`.
- `sidwave transform`, `format`, `diff`, `merge` and `generate`: the transformation library (transpose by voice or section, tempo, instrument swap, quantise, humanise, section order), canonical formatting with `--check` and `--write` for CI and pre-commit hooks, a semantic diff (exit 1 when the scores differ, `--json`), a three-way merge (exit 1 on conflicts, lists each conflict), and generation from a style, profile and seed with `--prg` and `--sid`. `sidwave diff --git` is a git external diff driver and `sidwave merge` works as a git merge driver; both are documented in `doc/authoring.md` and the merge driver is tested in a temporary repository.
- `diffSidwave(a, b, read, { compile: false })` skips the compile of both scores (`compiledEqual` is null); `sidwave diff` uses it unless `--compile` is given. `TransformValidation` has a new value `"arrange"` (parse the result and run every check of the compiler without assembling the note data) and `TransformOptions.inputChecked`; `sidwave transform` checks with `arrange` by default (`--validate parse|arrange|compile`) and parses the input once for a chain of operations.
- `mergeSidwave` kept the comments of the ours side only when the keys of its result happened to be in the same order as in the merged data; it now compares the in-place result to the merged data regardless of key order, so comments survive a merge in which both sides changed values.
- `bin.js` starts `--version` and the authoring commands without loading the other commands (the full command line takes about 0.2 s of CPU to load; `--version` now takes 0.03 s, `format --help` 0.1 s). An unknown command suggests the closest known one.
- `checkSidwaveCompiles` (`sidwave/compiler`): every check of `compileSidwaveToPrg` without assembling the note data (score rules, instrument table limits, the memory size and the `cpu: turbo` cycle budget), in about 70 % of the compile time; the default check of `sidwave transform`.
- The bundled example scores in `data/sound/examples` are now in canonical format (`sidwave format --check` passes). Their PRG and PSID output is byte-identical and every comment is kept; a comment at the end of a line moved to its own line. The scores of `learn/` keep their layout, because the tutorial quotes them verbatim.
- Sound effects too large for the 64 KB address space are reported as a score error (`$.effects`) by the PRG compile and the game build, instead of an assembler address error.
- CPU budgets for the authoring commands in `test/performanceBudgets.test.mjs`, and entries in `scripts/bench-perf.mjs`.
- SIDWave 1.5 (`sidwave: 1.5`): `player.soft_start`, `player.idle_writes` (true, false or `control`), `player.start`, `tuning` (`cents` and exact `registers` for single notes), wavetable steps with `reg`, pulse tables with width 0 and `wrap`, `speed` up to 8 and pattern rows down to 1/128 beat. A score that uses none of them compiles to the same bytes as under 1.4; each construct in an older document is an error that names the version and the field. See the chapter "Why a language change" in `data/sound/sidwave.md`. Asset libraries may declare `sidwave: 1.5`; `extract-instruments`, `checkInstrumentReuse` and `replaceWithImports` keep the version of a 1.5 source.
- `scripts/reconstruct-corpus.mjs` runs `sidwave reconstruct` over the 24 development tunes of the corpus manifest (held-out tunes are never run), caches the original traces and results by content, and writes `data/reconstruct/dev-report.json` and `dev-report.md` (verdicts, first differences, root-cause classes, score size, run time per minute of music). `reconstructSid` also returns the recompiled PSID and the phase timings.
- Recovery: exact note registers (`tuning.registers`) and exact `reg` pitch steps for instruments with a fixed pitch table, pulse tables with width 0 and wrap, a speed above 4, `player.soft_start: false` when the tune has no volume ramp, `player.idle_writes: false` or `control` for voices that stay unwritten, or write only their control register, until their first note, and `player.start` for the writes before the first note.

### Changed

- `convert` and `export` exit 5 (limit) instead of 3 when a score exceeds a fixed capacity of the target format, such as the 124 orderlist entries of SID-Wizard.
- `sidwave convert` and `sidwave info` detect a 15-sample MOD named `.mod` without `--from`.
- `sidwave convert` accepts `--sids 1-10` for MOD input; with another input it is a usage error.
- A JCH NewPlayer image of an unsupported version is detected, so `import` and `convert` report the unsupported version instead of an unknown format.
- MOD import reports the largest onset error in milliseconds when the speed or tempo changes inside a bar, instead of "up to one row".
- MOD import chooses the rows per beat by the fewest clamped bars, then the fewest mistimed rows.
- MOD sample analysis is faster and is cached by sample content.
- MOD sample names identify drums only as whole words (`Kickstart` and `Bride` are no longer drums).
- GoatTracker and Furnace export count time in video frames. A score with `speed: 2` or more was written at twice the intended tempo; the multispeed rounding is now reported as `timing.multispeed`.
- MIDI export writes drum hits on channel 10 (General MIDI percussion), and MusicXML export writes them as a separate unpitched percussion part, so that importing the file again keeps them as drum hits. The MIDI and MusicXML output changes for the shipped examples that contain drum hits: `chiptune_drive` (1.1 and 1.2), `funk_bass`, `stereo_echo`, `acid_line`, `ambient_filter` (1.1 and 1.2), `generated_ambient` and the reconstruct regression score `generator-seed1-silent-pitch`. Scores without drum hits give byte-identical output.
- MIDI, MusicXML, GoatTracker and Furnace import no longer report static sentences as losses. A loss is reported only when content was dropped, with its count (unread MIDI events, unread notation marks).
- `sidwave convert --verify` compares the output with the score after the import on note F1 (pitch, drum identity), pitch-only F1, duration overlap, voice agreement and drum identity, with an onset tolerance of one frame (20 ms) for formats without a grid, and half a row or grid cell plus 10 ms for row-based and quantising formats. For a MIDI source it also reports the same measures against the notes of the MIDI file itself (`sourceVsOutput`).
- Recovery clamps an instrument's hard restart to its shortest note in the emitted patterns, so scores with short notes at speed 5 and above compile. `player.start` writes are exact with the default `soft_start` (they bypass the volume ramp). Known limit: at speed 8 the first note is one call shorter than in the tune.

- `sidwave reconstruct`: a recovered score that the compiler rejects for its instrument-variant or table-step limit is repaired in recovery (least used instruments lose tables and vibrato, binary search, deterministic), so compiled examples reconstruct to a compiling score at 20 s and 60 s. An invalid recovered score is reported as `internalError` and exits with the `internal` category (70). The summary says when only the first 10 s were compared. After the start, `player.start` adds at most 10 cycles per call (measured at speed 1; the player entry is switched once), and the cycle estimate counts the start calls.

- Recovery (`reconstructSid`): the recovered score now compiles for more tunes. The block layout no longer produces negative pattern lengths, a hard restart is limited to eight frames and to the note length, notes outside the playable range, notes longer than 32 beats and notes shorter than a frame are limited or dropped and reported, and a table budget (63 instrument shapes, 255 steps per table kind) keeps the most used instruments complete. Loop folding of table steps is linear in the number of steps (was cubic), and the recovery takes about 1.6 s per minute of music for the recovery step in the development report (1.7 s for the whole reconstruction with staged verification, 7.9 s when every tune is verified over its whole horizon; was 10 s per minute before the linear fold) (was 10 s).
- Breaking (command line): an invalid score or unreadable input exits 3 (was 1 or 2), an unwritable output exits 3 (was 2), a failed verdict is the only exit 1; `--json` prints `{ ok, command, result | error: { category, message, details } }`; the engine yields to the event loop while rendering.

- Licence: GPL-2.0-or-later with the SIDWave Player Exception (`LICENSE-EXCEPTION.md`), replacing GPL-2.0-only.
- The dependency on `6502-toolkit` is `^0.1.0` (was the exact version `0.1.0`).
- `compileSidwaveToSid` accepts a `Uint8Array` for the PRG argument. This widens the parameter type (`Buffer` is a `Uint8Array`); callers are not affected. The compiler results (`CompileResult.prg`, `sid`) remain `Buffer`, because `sidwave` is a Node.js package and its callers use `Buffer` methods on them.
- `engines.node` is `>=20.19` (was `>=24`).
- Published files include `CHANGELOG.md` and `bin`.

### Fixed

- MOD import: the pitch of a looped sample now follows the cycle length of its loop. Before, every sample was treated as having a 64-point cycle, so a 32-point cycle was imported one octave low and other cycle lengths were off by the matching interval. `analyzeSample` reports the measured length as `loopCycle`. When the cycle of an audible loop cannot be measured reliably (noise, a chord, a quiet or very short tail, no clear period), the notes keep the 64-point pitch, the report lists the sample in `losses` and `analyzeSample` sets `loopUnmeasured`.
- MOD import: the sample finetune now moves the pitch in the ProTracker direction (nibble 0 to 7 raises it, 8 to 15 lowers it, in eighths of a semitone). Before, the sign was inverted, so a finetune of 4 or more in either direction could move a note by one or two semitones from the pitch the Amiga plays.

### Performance

- Compiling a score is 1.8 times faster over all examples (up to 2.6 times on `chiptune_drive`): the filter cutoff in Hz no longer scans all 2048 register codes on every lookup (now a precomputed table and a cache), stream compression compares integers instead of strings, and instrument variants are memoised. `lint`, `transpose`, `diff` and `merge` are faster by the same factor because they compile. `diff` also compiles only one side when both texts hold equal data. A1 comparison is 2.3 times faster (one half-size FFT per real window, no `Math.hypot`); the band energies were identical to the previous ones on every fixture tested. Similarity and quality analysis are 2 to 3 times faster (cached chroma tables and mono mix, a half-size FFT per frame). Parsing scores with synthesised samples is faster (the resampling kernel is computed once for integer rate ratios). Compiler output, PSID, game build and fixtures are byte-identical.
- Added `scripts/bench-perf.mjs` (CPU and wall time per operation, JSON report), `doc/performance.md` (budgets) and `test/performanceBudgets.test.mjs` (CPU-time regression tests).

### Documentation

- Name written as SIDWave in prose (README files, the language specification, the licence texts, the JSON Schema title, package descriptions, `--help` text and code comments). The npm package name, the `sidwave` command, file names, code identifiers, schema `$id` URLs, YAML keys, and error, lint and output messages (including `Invalid SIDWAVE at ...`) keep their spelling.

### Compatibility

- Language versions 1.0 to 1.3 are carried over unchanged; compiled output for existing scores is expected to be byte-identical to c64bridge 1.3.3. This is to be confirmed by the extraction gate.
